# 🎲 Game Night

Free multiplayer party games, strategy, and cooperative adventures in the browser, on phones and computers.
One player hosts a room, friends join with a 5-letter code. No sign-up, no game server.

## How it works (and why it's free)

| Piece | What it does | Cost |
|---|---|---|
| **GitHub Pages** (or Cloudflare Pages) | Serves the website files (HTML/JS/CSS) | Free for public repos, 100 GB/month traffic |
| **PeerJS cloud server** | Helps players find each other (matchmaking only) | Free community service |
| **WebRTC** | Players' browsers talk directly to each other | Free (built into browsers) |

The host's browser runs the game. Everyone else sends moves to the host and gets the updated board back.
If someone refreshes, they rejoin automatically. If the host refreshes, the room comes back with the same code.

## Put it online for free (GitHub Pages)

### Option A — no tools needed (upload in the browser)
1. Create a free account at https://github.com and click **New repository**.
   Name it e.g. `game-night`, choose **Public**, click **Create repository**.
2. Click **uploading an existing file**, then drag in everything in this folder
   (`index.html`, `css/`, `js/`, `games/`, `README.md`). Click **Commit changes**.
3. Go to **Settings → Pages**. Under *Build and deployment* pick **Deploy from a branch**,
   branch **main**, folder **/ (root)**, then **Save**.
4. After about a minute your site is live at `https://YOUR-USERNAME.github.io/game-night/`.

### Option B — with git
```bash
git init
git add .
git commit -m "Game Night"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/game-night.git
git push -u origin main
```
Then do step 3 above.

### Alternative: Cloudflare Pages
Create a free Cloudflare account → **Workers & Pages → Create → Pages → Upload assets**, and drag this folder in.

## Test it locally
```bash
node serve.js
```
Open http://localhost:8080 in two browser tabs: host in one, join with the code in the other.

Requires a current Node.js release (tested with Node 24). The development server binds to
`127.0.0.1` by default. Set `HOST` explicitly only if you intend to allow access from other machines.

## Checks

Run `node tools/test.mjs` for syntax checks, server and multiplayer regressions, rule scenarios,
and 50 simulated games at every supported player count. An optional number changes the simulation
count, for example `node tools/test.mjs 10`.

Install the pinned browser-test dependencies with `npm ci`, then run
`npx playwright install chromium webkit` and `npm run test:browser`.
The multiplayer suite uses a local PeerJS broker and real WebRTC between isolated Chromium contexts;
WebKit checks touch-sized library navigation and local play. It uses synthetic audio, never your microphone.
Traces and screenshots are written to `test-results/` and uploaded by CI. These checks do not replace
real-phone background/resume or difficult-network testing. Simulation logs include a `SEED` for replay;
set that environment variable and rerun the same game/player count to reproduce its random choices.

With the local server running, open `/tools/browser-test.html` and click **Run all games**
at phone and desktop viewport sizes. It reports render failures, horizontal overflow, and buttons
smaller than 30px. Open `/tools/local-boot-test.html` to exercise shared-device play without PeerJS.
Also verify hosting/joining in two tabs, moves in both directions, and guest/host refresh recovery.

Online rooms use the v2 protocol, with private reconnect credentials separate from public player IDs.
The host keeps only SHA-256 fingerprints of those secrets. Saved online sessions from v1 cannot be
safely resumed; create a new room. Saved shared-device games remain compatible.

**On GitHub**, every push runs `.github/workflows/test.yml`: the command-line checks above, and
`tools/browser-ci.mjs`, which loads the site in headless Chrome at phone and desktop widths, starts a
game, and renders every game for every seat. Results appear under the repository's **Actions** tab.

`games/catalog.js` is generated by `node tools/build-catalog.mjs` (and by `node tools/test.mjs`).
It lists every game's name, cover, rules and options so the home page loads without the games' code,
and it holds the site's version. Commit it with your changes; the GitHub check fails if it is stale.

## Reliability

- **Version check.** Players' copies of the site compare versions when they connect. If someone has a
  newer copy, the others see "A newer version is available" with an **Update now** button.
- **Backup host.** Migration is off by default. The host can choose a **Trusted backup host** in the lobby,
  marked **BACKUP HOST** when connected. If the host disappears for 15 seconds, the backup host
  reopens the room under the same code and everyone reconnects; the old host rejoins as a player.
  The copy contains the whole game, including hidden cards and puzzle answers. Only select someone you
  trust with that information. Disabling backups cannot retract information already received.
- **Stand-ins.** If a player drops out mid-game for 20 seconds, a computer plays their seat until they
  reconnect, so the table never stalls.
- **Less data.** After the first full copy, each update sends only what changed.
- **Bounded saves.** Rapid actions share a durable snapshot at most every 750 ms; game ends, tab hiding,
  and page exits flush immediately. An abrupt browser/process crash may lose up to that interval of moves.
  Storage quota failures do not stop online play. `node tools/reliability-test.mjs` includes a synthetic
  serialization benchmark; its mocked storage timings are not real device disk measurements.
- **Connection dots.** The dots in the top bar, the game bar and the lobby turn green, yellow or red with
  each player's delay to the host (hover for the milliseconds, and whether the connection goes through a relay).
- **Rematch.** When a game ends, the host's **Rematch** button keeps everyone in their seats (chess swaps
  colours); other players can tap **Ask for a rematch**.

## Playing a game

During a game the site's top bar gives way to a single game bar: the game's name and connection, the turn
timer, voice, **?** for the rules and **⋯** for everything else. The ⋯ menu (a sheet from the bottom on
phones) holds the room code and invite link, tournament standings, sound, how to play, New game and Back to
the lobby for the host, and Leave. Rules only open when someone taps **?**; until a game's rules have been
read once, its **?** button carries a gentle highlight. Dialogs fit the visible screen, and on phones they
rise from the bottom edge.

## Party games

- **Sketch Party** (2–8): each turn one player draws a secret word and everyone else races to type it.
  Letter hints appear as time runs down; faster guesses score more. The host picks rounds and drawing time.
- **Word Spies** (4–8): two teams, 25 words. Spymasters see the secret key and give one-word clues;
  teammates reveal words and must avoid the assassin.

`node tools/party-test.mjs` checks both games' rules, that guessers never receive the secret word or key,
and the tournament brackets.

## Voice chat

In an online room, tap the headset button (in the top bar, or the game bar during a game) to talk to
everyone else who joined voice. Tap the microphone to mute, and the hang-up button to leave. Audio goes directly between players' browsers, like the games. The browser asks for
microphone access the first time, and it needs the site on https (GitHub Pages is) or localhost.
Incoming callers must be on the host-authorized voice roster; the host binds their voice ID to their
authenticated data connection. Leaving voice stops audio tracks and closes calls.

## Finding a game

The library filters by type, supported group size, estimated duration, and difficulty (one row you can
swipe sideways on phones). In the lobby, the host's **Change game** opens every game as a cover, with games
that don't fit the current table marked. Cooperative
is a cross-category filter. Stars save favorites; recently played records games when they start.
Preferences stay in this browser without an account. Durations are editorial estimates, especially
for games with configurable rounds or clocks.

## Tournaments

A tournament spans several games, so it is a mode of the room rather than a setting of one game. In the
lobby the host switches from **One game** to **Tournament** (or taps **Host a tournament night** on the home
screen), then chooses:
- **Series**: pick several games; everyone plays each one, in the order picked, and every win scores a point.
- **Knockout**: one-on-one matches of one game in a bracket (byes for odd numbers, rematches after draws).
  Players not in the current match watch.
During a game, a trophy chip in the game bar opens the standings. After each game the host presses
**Next game ▸**; the last game crowns the champion.

## Chess computer levels

The host picks the computer's strength in the lobby: Easy (the built-in player) or Club, Strong and
Master, which use Stockfish at limited strength on the host's device.

## Spectators

Friends who open the room link after a game has started join as spectators: they see the live game
(without anyone's hidden cards or clues) but cannot move. In the lobby, anyone can press
**Just watch this game** to sit out the next game, or **Take a seat and play** to join it.

## Chess clocks

The host picks the chess clock in the lobby: no clock, 1, 3+2, 5, 10+5, 15+10 or 30 minutes. Each side's time
only runs on its own turn, White's starts after the first move, and running out loses (or draws if the
opponent has too little material to checkmate). Every screen's clock is synced to the host's time.

## If a friend can't connect
Most home Wi-Fi works directly. Some mobile networks block direct connections; the joining screen then
says the room exists but can't be reached, and suggests switching between Wi-Fi and mobile data.
For a lasting fix, sign up for a free TURN relay (Cloudflare Realtime TURN or the Metered free plan),
and add the `turn:` address, username and credential it gives you to `iceServers` in `js/config.js`.
Board games use only a few KB per move, so a free plan is plenty. Note that anything in `js/config.js`
is public on your site, so use credentials meant for browsers and keep the plan's usage limits on.

## Cooperative collection

- **Sunken Temple** (2–4): recover three relics and get every explorer home before the flood gates fail. Explorer, Engineer, Scholar, and Diver have different abilities.
- **Emberwatch** (2–4): carry four rescued animals to River Camp while protecting villages from wind-driven wildfire. Ranger, Firefighter, Medic, and Weatherkeeper share the mission.

Both games offer Relaxed, Standard, and Daring expeditions, shared team victories and defeats,
computer teammates, illustrated boards, and in-game rules. To play alone, choose **One device**,
remove Player 2, and add a computer teammate. The first player chooses difficulty after Start game.

`node tools/coop-test.mjs` exercises all supported team sizes and difficulty levels, validates
illegal actions and JSON state, and checks selected victory, defeat, and role-ability scenarios.

## Escape rooms

- **The Missing Keeper** (1–4): locked inside an abandoned clocktower, search the workshop, study,
  gear loft and belfry, repair the great clock, and find out what happened to its keeper.
- **Signal from Below** (1–4): restore power to a deserted underwater station, compare recordings,
  decode a repeating signal and rescue the crew. Each diver's wrist terminal holds different clues,
  so the team has to talk (or share fragments into the journal).

There are no turns: everyone explores at once. Rooms are illustrated with tappable objects and close-ups,
items go into a shared inventory, clues anyone examines are copied to a team journal, and hints get more
specific each time the team asks. Codes are reshuffled every game. Computer teammates explore and share
straight away, but only solve a puzzle after the team has made no progress for 45 seconds.
Both games are built on `games/escape-kit.js`, which takes rooms, objects, items, puzzles and hints as data.

`node tools/escape-test.mjs` plays bot teams of every size, checks that answers and other players' private
clues never appear in a player's view, and runs scripted solves with wrong tries, locked rooms and hints.

## Adding another game
Each game is one file in `games/`. See the comment at the top of `games/index.js` for the format,
then add it to the `GAMES` list and run `node tools/build-catalog.mjs`.

The site code is in `js/`: `state.js` (room state, saved sessions, game catalog), `net.js` (rooms,
networking and the host's rules), `ui.js` (screens) and `app.js` (start-up).
